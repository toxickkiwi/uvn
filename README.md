# CRM «Учёт в народ»

Внутреннее веб-приложение для менеджера по продажам. Все данные лежат в Google Таблице, приложение — удобный интерфейс к ней. Работает только на Google: таблица + Apps Script, без своих серверов и платных сервисов.

Техническое задание — [docs/ТЗ.md](docs/ТЗ.md).

> **Статус: этапы 1–3 из 7.** Работают экраны «Сегодня», карточка сделки, «Новое обращение», поиск, шаблоны в карточке, самопроверка (**CRM → Запустить самопроверку**). Дальше: «Воронка» и вкладка «Шаблоны» (этап 4), отчёт (5), Telegram (6).

## Как пользоваться

- **Сегодня** — три блока: «Просрочено», «На сегодня», «Без ответа». Кнопка **«Написал»** добавляет касание и переносит задачу на завтра 10:00, **«+1 день»** — просто переносит задачу. Клик по строке открывает карточку.
- **+ Обращение** (или клавиша **N**) — канал, контакт (ник, ссылка, почта, телефон — что угодно), имя, запрос. Если клиент уже есть, приложение покажет его до сохранения.
- **Карточка сделки** — слева клиент (поля правятся щелчком), в центре история и **Шаблоны**, справа сделка. Всё сохраняется само при выходе из поля.
- **Поиск** (клавиша **/**) — по имени, нику, почте, телефону, номеру сделки.

## Как развернуть (для человека без опыта программирования)

Займёт около 20–30 минут. Всё делается под тем Google-аккаунтом, который будет **владельцем** таблицы (лучше — общий рабочий аккаунт школы, а не личный аккаунт сотрудника).

### Шаг 1. Загрузить таблицу в Google Диск

1. Откройте [drive.google.com](https://drive.google.com).
2. Перетащите файл `CRM_стартовая_таблица.xlsx` в окно Диска.
3. Нажмите на загруженный файл правой кнопкой → **Открыть с помощью → Google Таблицы**.
4. Откроется копия в формате Google Таблиц. Работать будем с ней. Исходный `.xlsx` можно удалить, чтобы не путаться.
5. Проверьте, что внизу есть листы: Клиенты, Сделки, Касания, Тарифы, Справочники, Шаблоны, Пользователи, Настройки.

### Шаг 2. Вписать сотрудников

1. Откройте лист **«Пользователи»**.
2. В колонку **«Почта»** впишите Google-почту каждого сотрудника (например, `maxim.uvn@gmail.com`) — ту, под которой человек входит в Google.
3. Колонка «Роль»: `менеджер` или `руководитель`. Колонка «Активен»: `TRUE` — доступ есть, `FALSE` — доступ закрыт.
4. Нажмите **«Настройки доступа»** (зелёная кнопка справа вверху) и добавьте те же почты с правом **«Редактор»**.

> Почему нужны оба шага: приложение работает от имени того, кто его открыл. Без доступа к таблице человек физически не увидит данные, а без строки в «Пользователи» приложение покажет «Нет доступа».

### Шаг 3. Создать скрипт внутри таблицы

1. В таблице откройте меню **Расширения → Apps Script**. Откроется редактор в новой вкладке.
2. Слева вверху нажмите на «Проект без названия» и назовите проект `CRM`.
3. Нажмите на шестерёнку **«Настройки проекта»** (слева) и включите галочку **«Показывать файл манифеста appsscript.json в редакторе»**.
4. В разделе **«Часовой пояс»** там же выберите `(GMT+03:00) Москва`.

### Шаг 4. Скопировать код

Код лежит в папке `src` этого репозитория. Каждый файл нужно перенести в редактор Apps Script.

1. Вернитесь в **«Редактор»** (значок `< >` слева).
2. Откройте файл `appsscript.json` в редакторе, удалите всё содержимое и вставьте содержимое файла [`src/appsscript.json`](src/appsscript.json).
3. Файл `Код.gs` (он создан автоматически) переименуйте в `Main` и замените его содержимое на [`src/Main.gs`](src/Main.gs).
4. Для каждого из остальных `.gs`-файлов нажмите **«+» → «Скрипт»**, введите имя **без** `.gs` и вставьте содержимое:
   `Db`, `Rules`, `Api`, `Report`, `Telegram`, `Setup`, `Tests`.
5. Для каждого `.html`-файла нажмите **«+» → «HTML»**, введите имя **без** `.html` и вставьте содержимое:
   `Index`, `Styles`, `App`, `NoAccess`.
6. Нажмите значок дискеты **«Сохранить проект»** (или Ctrl+S).

Имена файлов важны: `Index`, `Styles`, `App`, `NoAccess` должны называться ровно так.

> Если рядом есть разработчик, вместо копирования он может загрузить код одной командой через `clasp` — см. раздел «Для разработчика».

### Шаг 5. Подготовить таблицу

1. Вернитесь во вкладку с таблицей и **обновите страницу** (F5).
2. Через несколько секунд в меню появится пункт **«CRM»**.
3. Выберите **CRM → Подготовить таблицу**.
4. Google попросит разрешение: **«Продолжить»** → выберите свой аккаунт → появится экран «Google не проверял это приложение» → **«Дополнительные настройки»** → **«Перейти на страницу CRM (небезопасно)»** → **«Разрешить»**.
   Это нормально: приложение ваше собственное и не проходило проверку Google, потому что не публикуется для всех.
5. Снова выберите **CRM → Подготовить таблицу**. Появится сообщение «Готово». На стартовой таблице менять ничего не придётся.

Функцию можно запускать сколько угодно раз: она только добавляет недостающие листы, колонки, выпадающие списки и настройки и никогда не меняет и не удаляет данные.

### Шаг 6. Опубликовать веб-приложение

1. В редакторе Apps Script нажмите синюю кнопку **«Начать развертывание» → «Новое развертывание»**.
2. Слева у «Выберите тип» нажмите шестерёнку → **«Веб-приложение»**.
3. Описание: `CRM`.
4. «Запуск от имени»: **«Пользователь, который открывает веб-приложение»**.
5. «У кого есть доступ»: **«Все, у кого есть аккаунт Google»**.
6. Нажмите **«Начать развертывание»** и скопируйте **URL веб-приложения** (заканчивается на `/exec`). Это адрес CRM — сохраните его в закладки и отправьте сотрудникам.

Ссылку также можно открыть из таблицы: **CRM → Открыть приложение**.

### Шаг 7. Первый вход сотрудника

Каждый сотрудник при первом открытии ссылки один раз увидит тот же экран разрешений, что в шаге 5: **«Дополнительные настройки» → «Перейти…» → «Разрешить»**.

- Если человек видит **«Нет доступа»** — на странице написана почта, под которой он вошёл. Проверьте, что именно она вписана в «Пользователи», а «Активен» = `TRUE`.
- Если вошли не под той почтой — выйдите из Google или откройте ссылку в другом профиле браузера.

### Как обновить приложение после изменений кода

Обновлять нужно только файлы, которые изменились — в сообщении к обновлению будет их список.

1. Замените содержимое изменённых файлов в редакторе Apps Script и сохраните.
2. **«Развертывание» → «Управление развертываниями»** → карандаш у вашего развертывания → «Версия»: **«Новая версия»** → **«Развернуть»**.

Адрес приложения при этом не меняется.

## Что можно править прямо в таблице

| Лист | Что можно | Чего нельзя |
|---|---|---|
| Справочники | Дополнять «Каналы», «Способы оплаты», «Причины отказа» | Менять значения «Стадии», «Потоки», «Типы касаний» — на них завязана логика |
| Тарифы | Цены, новые тарифы, «Активен» = FALSE для скрытия | — |
| Шаблоны | Тексты, новые шаблоны, «Активен» | Менять переменные: допустимы только `{Имя}`, `{Курс}`, `{Тариф}`, `{Сумма}`, `{Менеджер}` |
| Пользователи | Добавлять сотрудников, закрывать доступ («Активен» = FALSE) | — |
| Настройки | Значения | Названия ключей |

**На любом листе нельзя переименовывать листы и заголовки колонок** — по ним приложение находит данные. Колонки можно переставлять местами.

Изменения справочников подхватываются приложением сразу (при ручной правке) или в течение 5 минут.

## Отклонения от ТЗ

1. **Добавлено разрешение `script.container.ui`** в `appsscript.json`. Без него меню «CRM» и всплывающие окна в таблице не работают, когда список разрешений задан явно.
2. **Добавлен файл `NoAccess.html`** — страница «Нет доступа». В структуре из ТЗ её не было, но так её проще править, чем строку в коде.
3. **Добавлен простой триггер `onEdit`**: сбрасывает кэш справочников при ручной правке листов «Справочники», «Тарифы», «Шаблоны», «Пользователи», «Настройки». Иначе изменения были бы видны только через 5 минут.
4. **В колонках «ID GetCourse», «Телефон», «Номер заказа GetCourse», «Telegram chat ID»** `setupSpreadsheet()` ставит формат «Обычный текст», чтобы Google Таблицы не превращали номера в числа. Значения при этом не меняются.
5. **Правило 4.5 для старых клиентов.** В импорте у 36 из 48 клиентов нет ни одного контакта. Контакт обязателен при создании клиента и запрещено стирать последний контакт; у клиентов, которые пришли без контактов, остальные поля править можно (жёлтая плашка «Проверить» остаётся).
6. **Правило 4.9.** Дата задачи в прошлом сервером принимается всегда; интерфейс предупреждает. Дата создания проверяется только при создании сделки, чтобы старые записи с ошибочной датой можно было править.
7. **Телефон.** Российские номера приводятся к 7XXXXXXXXXX. Номера других стран (11–15 цифр) сохраняются как есть; короче 11 цифр — ошибка.
8. **Авто-переход «Новое» → «В диалоге»** срабатывает на любое касание, которое добавил менеджер (все типы, кроме системных «Обращение» и «Смена стадии»).
9. **«Сегодня».** Сделка из блока «Без ответа» не дублируется в «Просрочено» / «На сегодня». Открытая сделка без даты задачи (бывает в импорте) показывается в «Просрочено».
10. **Ответы API.** `createDeal` при найденных дублях (без `force`) ничего не создаёт и возвращает `{ duplicates: [...] }`. `updateDeal` возвращает `{ deal, newTouches }` — сделку и касания, которые записала система (например, «Смена стадии»), чтобы интерфейс не перечитывал карточку целиком.
11. **Причина отказа** при повторном открытии сделки из «Отказ» не стирается — остаётся в истории.
12. **Даты задач без времени** (00:00, так пришли из старой таблицы) показываются без времени: «01.10».
13. **Кнопка «← Сегодня»** в карточке ведёт на «Сегодня», а не «назад по истории»: приложение работает внутри рамки Google, и история браузера там ненадёжна.
14. **Вкладки «Воронка», «Шаблоны», «Отчёт»** пока скрыты — появятся на этапах 4–5.
15. **Часовой пояс таблицы.** `setupSpreadsheet()` ставит таблице пояс Europe/Moscow: таблица, загруженная из .xlsx, получает пояс аккаунта, и даты в ней показываются со сдвигом.
16. **Настройки читаются как текст ячейки.** Google Таблица превращает «10:00» во время с датой 1899 года; если читать его как дату, часы сдвигаются из-за исторического смещения часового пояса.

## Для разработчика

- Код — обычный JavaScript для V8, без сборки. `src/` — содержимое проекта Apps Script.
- Загрузка через [clasp](https://github.com/google/clasp): впишите `scriptId` (Настройки проекта → «Идентификатор скрипта») в `.clasp.json`, затем `clasp login` и `clasp push`.
- `dev/` — локальный симулятор Apps Script для проверки логики без Google. В Apps Script не загружается.

```bash
pip install openpyxl
python3 dev/xlsx_to_json.py CRM_стартовая_таблица.xlsx dev/fixtures/start.json
node dev/check-stage1.js dev/fixtures/start.json
node dev/check-stage2.js dev/fixtures/start.json   # runSelfTests() + API на стартовых данных

# интерфейс в браузере: локальный сервер + сценарий Playwright
PREVIEW_NOW=2026-10-04T09:00:00Z node dev/preview.js dev/fixtures/start.json 8788
node dev/ui-check.js http://localhost:8788
```

Таблицы с данными клиентов (`*.xlsx`, `dev/fixtures/`) в репозиторий не коммитятся.
